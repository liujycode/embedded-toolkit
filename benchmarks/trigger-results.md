## 判定方法（为什么不能靠文本匹配）

技能名会出现在系统提示的技能清单里（Claude Code 的 `slash_commands`、OpenCode 的技能列表），任何"技能名出现即触发"的文本匹配会把全部用例误判为触发（已实测确认）。本记录只认结构化信号：

- **Claude Code**：`Launching skill: <技能>` 事件、`commandName` 成功回执；另加"带技能安装路径（`skills/<技能>/scripts/...`）的脚本调用"作为执行级证据（技能文档里的示例命令不算）。
- **OpenCode**：`tool="skill"` 且 `name=<技能>` 的加载事件；`tool="bash"` 且命令含脚本调用。

解析容错：BOM、字符串内终端转义字符、破损行（原始行兜底需同时出现工具类型与名称/脚本）。

复现命令：

```
# Claude Code
claude -p "<prompt>" --output-format stream-json --verbose --allowedTools Skill Bash Read Glob Grep
# OpenCode
opencode run --format json --auto "<prompt>"
# 判定
python tools/trigger_eval.py --dir <输出目录> --agent claude|opencode
```

## 方法学备注（引用数字时必须同时说明）

1. 无头单次会话、自动批准工具，与交互式使用存在行为差异。
2. Claude Code 侧模型经 CC Switch 代理（deepseek-v4-flash），非 Anthropic 原版模型；代理会丢部分事件块。
3. 判定只看"技能是否被加载 / 脚本是否被调用"，不评价答案质量。
4. 每例仅运行一次，未做多次重复；第二轮已用全量 20+10。
5. 用例中的无芯片/无本地 SVD 场景（如 STM32G431、ESP32）也会触发技能并走"未找到"路径——这是预期行为，不影响触发判定。
