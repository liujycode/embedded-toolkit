# 核验规则细节（E01–E10）

每条规则给出：判定方式、示例（会报 / 不会报）、桶与标签。所有判定只依赖 SVD 与代码文本；
**不确定时进"未判定"**，不产生错误。

## E01 外设不存在（报 / 已核验 / 高）

- 判定：`外设->寄存器` 的"外设"是形如 `USART1`/`TIM2` 的全大写标识符，但在 SVD 的外设清单里不存在。
- 会报：`TIM2->CR1 |= TIM_CR1_CEN;`（芯片 SVD 中只有 TIM1）
- 不会报：`hi2c1->Init` 这类小写/驼峰局部指针（静默忽略）；`SysTick->CTRL`（内核外设 → 未判定）；
  `DMA1_Channel1->CCR`（疑似簇寄存器命名 → 未判定）。
- 提示：给出编辑距离最近的 3 个外设名。

## E02 寄存器不存在（报 / 已核验 / 高）

- 判定：外设存在，但寄存器名不在该外设的寄存器清单里。
- 会报：`USART1->CR9 = 1;`（应为 CR1）
- 不会报：`DMA1->CH1`（簇前缀 → 未判定）。

## E03 字段宏不存在或与寄存器不符（报 / 已核验 / 高）

- 判定：把全大写（或 `_Msk`/`_Pos` 后缀）的标识符按 CMSIS 约定映射到"外设 → 寄存器 → 位域"：
  1. 去掉 `_MSK/_MASK/_POS/_SHIFT` 后缀；
  2. 前缀匹配外设家族名（`USART1`→`USART`、`GPIOA`→`GPIO`、`TIM1`→`TIM`、`DMA1_Channel1`→`DMA`）；
  3. 剩余部分尝试各种切分，找"寄存器名 + 位域名"（寄存器名支持前缀匹配，如宏 `CCMR1` 对应 SVD 的 `CCMR1_Output`）；
  4. 位域名后多出的部分是枚举名时视为枚举值宏（如 `USART_CR1_PS_ODD`）。
- 会报：
  - `USART1->CR1 |= USART_CR1_XXX;`（位域 XXX 不存在）
  - `USART1->CR1 |= USART_BRR_DIV;`（宏属于 BRR，写的是 CR1）
  - `USART1->CR1 |= USART_CR1_PS_EVEEN;`（PS 之后的 EVEEN 不是枚举名，疑似拼写错误）
- 不会报：`USART_CR1_PS_ODD`（合法枚举宏）；文件内 `#define` 能解析的数值宏（如 `UART_BAUD_VALUE`）。

## E04 值超出宽度（报 / 已核验 / 高）

- 判定：右值（或 `MODIFY_REG` 的置位值）能求值，且超过目标寄存器/位域位宽。
- 会报：`TIM1->CR1 = 0x1FFFF;`（16 位寄存器）；`MODIFY_REG(CR1, PS_Msk, 0x4)`（1 位位域）。
- 不会报：值中含变量、函数调用等无法求值时（进"未判定"）。

## E05 枚举值不合法（报 / 已核验 / 中）

- 判定：`MODIFY_REG` 的清位掩码能映射到唯一一个位域、置位值可求值，而该值不匹配任何枚举
  （`enumeratedValues`，含 `#1xx` 这类任意位模式）。
- 会报：`MODIFY_REG(TIM1->CR2, TIM_CR2_MMS_Msk, 0x2);`（MMS 只有 RESET/ENABLE/COMPARE）
- 不会报：值与某个枚举匹配（含掩码匹配）。

## E06 无效清位（报 / 需查手册 / 低）

- 判定：`CLEAR_BIT(reg, FIELD)` 或 `reg &= ~FIELD`，对应位域的复位值为 0，且**本文件**中从未出现
  对该位域的置位（`|=`、`SET_BIT`、可求值的直接写等）。
- 会报：先清 `USART1->CR1.M0`，但全文件都没有置位过 M0。
- 不会报：`MODIFY_REG` 的清位掩码（属于常规用法，不报 E06）。
- 注意：这是"低严重度"提示，可能是有意为之。

## E07 访问前未见时钟使能（报 / 需查手册 / 中）

- 判定：写入某外设（如 `USART2`）时，在 **RCC** 中能找到名为 `<外设>EN` 的位域（如 `APB1ENR.USART2EN`），
  但本文件里既没有对该位域的置位，也没有 `__HAL_RCC_USART2_CLK_ENABLE()` 之类的使能宏调用。
- 会报：`USART2->CR1 |= USART_CR1_UE;` 而全文件没有开 USART2 时钟。
- 不会报：先 `RCC->APB1ENR |= RCC_APB1ENR_USART2EN;`，或存在 `__HAL_RCC_USART2_CLK_ENABLE()`。
- 边界：**文件级**判定。使能写在其它文件时是误报，请加 `--no-clock-check`；RCC 里找不到 `<外设>EN`
  时跳过该外设（不报）。

## E08 硬编码地址（报 / 已核验 / 高）

- 判定：`*(volatile uint32_t *)0x...` 形式的直接地址写入；用地址反查给出对应寄存器名（若有）。
- 会报：`*(volatile uint32_t *)0x40013800 = 1;`（= USART1.CR1）
- 说明：该形态本身即报；SVD 中查不到对应寄存器时也报，只是没有寄存器名。

## E09 中断分组多处设置（报 / 需查手册 / 中）

- 判定：同一文件出现多处 `NVIC_SetPriorityGrouping`。
- 会报：两处 `NVIC_SetPriorityGrouping(3);`——互相覆盖，需确认哪一处生效。

## E10 写只读寄存器或位域（报 / 已核验 / 高）

- 判定（三种都算）：
  1. 目标寄存器 `access` 为 `read-only`；
  2. 写入表达式中映射到的位域 `access` 为 `read-only`（含 `SET_BIT/CLEAR_BIT/MODIFY_REG` 的参数）；
  3. 直接写的数值命中了寄存器中只读位域的位（如 `RCC->CR = 0x400` 命中只读的 `HSIRDY`）。
- 会报：`USART1->SR = 0x20;`（SR 只读）；`RCC->CR = 0x400;`（HSIRDY 只读）。

## 输出分桶

| 桶 | 内容 |
|---|---|
| 报 | 上面任一 E 规则命中 |
| 未判定 | 范围外或无法确定：HAL 调用、簇命名、内核外设、无法映射的宏、值无法求值等，逐条给出原因 |
| 通过 | 命中写入形态、能映射、未触发任何规则 |

复查清单（`--checklist`）分组：芯片默认（写入等于复位值）/ 已核验 / 需查手册（E06/E07/E09 与未判定）/ 需实测（涉及 DMA、NVIC、SysTick 的写入）。
